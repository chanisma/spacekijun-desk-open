# 스페이스기전 데스크

## 실행 파일

`dist/SpacekijunDesk.exe`는 Python 설치 없이 실행하는 단일 Windows 실행 파일입니다. **두 번 눌러 켜면 독으로 시작합니다**(`스페이스기전-독.bat`과 같음). 데스크 본창은 독의 `데스크`나 트레이 메뉴의 `데스크 열기`로 엽니다 — **어떻게 켜지든(업데이트 뒤 다시 켜질 때 포함) 본창은 숨긴 채 독만 뜹니다**(2026-10-25 요청, 본창까지 보이려면 `--desk`). 트레이 아이콘을 누르면 독(위젯)이 앞으로 옵니다(꺼져 있었으면 켭니다). Microsoft Edge와 WebView2 Runtime이 PC에 설치되어 있어야 합니다. 별도 Playwright Chromium 설치는 필요하지 않습니다. 개인 로그인 정보와 인증서·Solar API 키는 포함하지 않으며 이 PC의 기존 저장소를 사용합니다. 다른 PC에서 Solar 요약을 사용하려면 해당 PC의 `%LOCALAPPDATA%/SpacekijunDesk/upstage.key`에 API 키를 별도로 설정해야 합니다.

아이콘은 사용자가 제공한 `spacekijun-desktop-v1.2.0.exe`의 원본 아이콘 리소스를 추출하여 실행 파일과 트레이에 적용했습니다.

다시 빌드:
```powershell
python -m pip install -r app/requirements.txt PyInstaller==6.22.2
python -m PyInstaller --noconfirm --clean SpacekijunDesk.spec
```

### 자동 업데이트 (교사판 · 학생판)

켜져 있는 데스크가 새 판을 스스로 받아 **묻지 않고** 바꿉니다(`core/updater.py`). 판 번호는 `core/edition.py` 의 `DESK_VERSION`, 트레이 아이콘에 마우스를 올리면 보입니다.

- **확인·받기:** 켜고 5초 뒤(켠 직후 인터넷이 없으면 30초 간격으로 여섯 번 더)와 6시간마다 Supabase Storage `desk-releases/teacher/latest.json`(공개 읽기)을 읽어, 더 새 판이면 조각(20MB)을 받아 이어 붙이고 조각마다·전체의 SHA-256 을 맞춘 뒤 `%LOCALAPPDATA%/SpacekijunDesk/update/` 에 둡니다.
- **서명:** 목록은 Ed25519 로 서명되어 있고(`core/ed25519.py`, RFC 8032), 앱에 박힌 공개 키로 확인될 때만 받습니다. 서명 키는 배포 PC 의 `.secrets/desk-update.key`(DPAPI)에만 있습니다 — 저장소에 무엇이 올라가도 데스크는 서명 없는 것을 깔지 않습니다. 버킷 쓰기는 관리자(`is_admin()`)만(spacekijun `supabase/migrations/20261013222302_desk_releases_bucket.sql`).
- **바꾸기 (2026-10-26 부터 묻고):** 켤 때마다 받아 둔 새 판이 있으면 «지금 업데이트할까요?»를 묻고, 켜 둔 동안 새로 받으면 그때 묻습니다(맨 위에 뜨는 Windows 창). «아니요»면 지금 판을 그대로 쓰고 다음에 켤 때 다시 묻습니다. 같은 판은 켜 둔 동안 한 번만 묻습니다. 그전(1.3.34·1.0.33 까지)은 묻지 않고 다음에 켤 때나 20분 넘게 손을 놓은 틈에 바꿨습니다. 예를 누르면 받아 둔 새 실행 파일을 **설치 모드**(`--install-update <자리> --wait <pid,…> --then <인자…>`)로 띄우고 옛것은 그냥 끝납니다. 새것이 옛것의 두 프로세스(파이썬·부트로더)가 끝나길 기다려 제 몸을 원래 자리에 덮어쓰고 `--after-update` 로 새 판을 띄웁니다. 덮어쓰지 못하면 옛것을 그대로 다시 띄웁니다(`update/install-error.log`). 바뀌면 트레이 알림이 뜹니다.
- 🚨 옛것이 돌면서 제 실행 파일을 비키고 새것을 놓으면 안 됩니다 — 한 파일 실행 파일은 모듈을 그 경로의 파일에서 그때그때 읽어, 바꾼 뒤 무엇이든 불러오면 `Error -3 while decompressing data` 오류 창을 남기고 죽습니다(2026-10-13 확인, 1.3.3 까지의 방식).
- **손으로 하기 (2026-10-14):** 설정의 **프로그램 업데이트**(현재 판 표시 · [업데이트 확인] → 새 판을 받으면 [지금 업데이트]) 또는 트레이 메뉴의 **업데이트 확인 / 지금 업데이트 (판)**. 확인·받기는 정기 확인과 같은 `Checker`(서명·조각 확인 그대로, 둘이 겹치지 않게 잠금)로 하고, 바꾸기는 손 놓기를 기다리지 않고 바로 — 새 판은 창을 보이며 다시 켜집니다. 로그인·나이스 도우미·업무시스템 창이 열려 있으면 설정에서는 한 번 더 묻고, 트레이에서는 하지 않고 까닭을 알립니다. API: `update_status` · `update_check` · `update_apply`.
- 쓰지 않는 경우: 소스로 돌릴 때, 교사판 실행 파일 폴더에 쓸 수 없을 때(Program Files 등).
- 🚨 폴더에 쓸 수 있는지는 `tempfile` 로 보면 안 됩니다 — Windows 에서 ACL 로 막힌 폴더의 `PermissionError` 를 이름 겹침으로 보고 `TMP_MAX`(약 21억) 번 다시 해 켤 때 멈춥니다(2026-10-16 학생판 1.0.6 시험에서 확인, 내보내기 전에 고침). `installable()` 은 한 번만 만들어 봅니다.
- **학생판 (2026-10-16):** 같은 방식으로 `desk-releases/student/latest.json` 을 봅니다(판 번호 `STUDENT_VERSION`, 같은 서명 키, 목록의 `app` 이 `SpacekijunStudent` 여야 받음). 트레이 메뉴에 **업데이트 확인 / 지금 업데이트**가 있고, 켤 때 묻는 것도 교사판과 같습니다.
  Intune 판은 학생이 쓸 수 없는 Program Files 에 있어서, 새 판을 **그 학생의 사본** `%LOCALAPPDATA%/SpacekijunStudent/app/SpacekijunStudent.exe`(+`version.json`: 판·크기·SHA-256)에 놓습니다(`updater.target()`·`user_copy()`). Program Files 의 것은 켤 때(자동 실행 포함) 사본이 자기보다 새 판이고 내용이 표식과 맞으면 사본을 같은 인자로 띄우고 끝납니다(`updater.handoff`, `student.py`). Intune 이 같거나 더 새 판을 깔면 사본을 지웁니다. 학교가 사용자 폴더의 실행 파일을 막아 사본을 띄우지 못하면 Program Files 의 것으로 그대로 켜고, 처음 놓다 실패하면 `--fallback` 으로 지금 것을 다시 띄웁니다. Intune 탐지 규칙(HKLM `Version`)은 Intune 이 깐 판 그대로라 Intune 쪽은 영향이 없습니다.
- **새 판 내보내기:** `DESK_VERSION` 을 올리고 → 빌드 → `python deploy/desk-update/publish.py`. 학생판은 `STUDENT_VERSION` 을 올리고 → `deploy/intune/build.ps1` → `python deploy/desk-update/publish.py --student --exe <SpacekijunStudent.exe>`. 자체 점검·판 번호·이전 판보다 새것인지 확인하고 서명해 올린 뒤, 공개 주소에서 다시 받아 확인합니다. 처음 한 번은 `--key` 로 서명 키를 만들었습니다(키를 잃으면 새 공개 키를 넣은 판을 손으로 한 번 다시 깔아야 합니다).

실행 파일 자체 검증(실제 계정 로그인·쪽지 감시·발송 없이 WebView2와 Edge 드라이버 확인):
```powershell
.\dist\SpacekijunDesk.exe --self-test "$env:TEMP\spacekijun-package-check.json"
```

`dist/SpacekijunNeis.exe` 는 **나이스 하나만** 프로그램 안 창에서 여는 작은 실행 파일입니다(`app/neis_desk.py`, `SpacekijunNeis.spec`). Playwright 를 아예 넣지 않아 가볍지만 **도우미 패널이 없습니다.** 데스크 본체는 나이스를 Edge 에서 열고 도우미를 붙입니다.

`스페이스기전-데스크.bat` 또는 `python app/main.py`로 실행합니다. Windows WebView2에서 로컬 HTML/CSS 화면을 표시하고 `app/core`의 기존 Python 기능에 연결합니다. 화면 파일과 Pretendard 글꼴은 앱에 포함되어 있습니다.

처음 설치하는 PC:
```powershell
python -m pip install -r app/requirements.txt
```
Microsoft Edge와 WebView2 Runtime이 필요합니다. 나이스·업무포털·에듀파인은 설치된 Edge로, 리로스쿨·AIEP는 프로그램 안 창으로 열립니다. `스페이스기전.bat`는 기존처럼 스페이스기전 웹사이트를 엽니다.

- **업무 홈:** 스페이스기전, NEIS, 전북 업무포털, K-에듀파인 바로가기. 에듀파인은 저장된 업무포털 아이디와 인증서로 자동 로그인만 수행하며 분석·자료 수집 기능은 없습니다. 자동 로그인 다섯 곳은 두 갈래로 열립니다 — 인증서를 쓰는 나이스·업무포털·에듀파인은 설치된 Edge에서, 리로스쿨·AIEP는 데스크 안 창에서. 어느 쪽이든 서비스마다 창이 따로입니다. 첫 실행에서는 보안프로그램 권한 허용을 한 번 물을 수 있습니다.
- **쪽지함:** 최근 60개 받은 쪽지·답장, 전문 확인, 새로고침.
- **스티커 메모:** Windows 스티커 메모처럼 메모마다 작은 창을 띄웁니다. 입력을 멈추면 자동 저장하고, 색 7가지·항상 위·삭제를 창 메뉴에서 고릅니다. 메모는 SPACEKIJUN 협업노트(`collab_notes`)의 개인 보드 **‘내 스티커 메모’**(`meta.kind = 'desk_sticky'`)에 저장되어 웹의 협업노트에서도 같은 메모를 보고 고칠 수 있습니다(메모 창을 누르거나 마우스를 올리면 곧바로, 최근 2분 안에 만진 메모는 20초마다, 그 밖에는 5분마다 웹의 수정을 받아 옵니다. 키보드·마우스를 10분 넘게 놓으면 묻지 않습니다). 이 보드는 **본인만** 볼 수 있습니다 — DB가 항상 private로 고정하고, 멤버 초대를 막고, 교직원 전체 보드 열람 예외에서도 뺍니다(SPACEKIJUN `supabase/migrations/20261008130000_desk_sticky_notes.sql`). 창 위치·크기·항상 위·열려 있던 메모는 이 PC의 `%LOCALAPPDATA%/SpacekijunDesk/sticky-windows.json`에만 기억하고, 다음 실행 때 열려 있던 메모 창을 다시 띄웁니다. 로그아웃하면 메모 창을 모두 닫습니다.
- **교직원 명부:** 조직도 동기화, 검색, 별칭 저장.
- **연결 및 설정:** 인증서 암호화 저장, SPACEKIJUN 로그인, 쿨메신저 상태 확인.
- **사용 방법:** 상단 버튼에서 10단계 화면 시연을 엽니다. 계정 연결, 인증서 선택, 바로가기, 알림·답장, 쪽지함, 명부, 프로필의 개인기기·자동 로그인, 트레이 종료를 안내합니다. `이전·다음·다시 재생`으로 직접 조작하며, 안내는 실제 설정을 변경하지 않습니다.
- **인증서 사용자 이름:** 인증서에 포함된 사용자 이름을 입력하면 NEIS·업무포털·에듀파인에 공통 적용합니다. 일치하는 인증서가 하나일 때만 암호를 입력합니다. 이름이 없거나 일치 항목이 여러 개면 자동 로그인을 중단하고 안내합니다. 설정 이름을 비우면 목록에 인증서가 하나일 때만 선택합니다. 같은 이름의 인증서가 여러 개라면 인증서 이름 전체나 구분 문구를 입력하세요. 저장 시 암호 칸을 비우면 기존 암호를 유지합니다.
- **자동 감시:** 연결된 계정이 있으면 앱 실행 시와 로그인 완료 시 자동 시작하며 중단된 감시 스레드는 10초 간격으로 다시 확인합니다. 창을 닫으면 트레이에서 계속 실행합니다. 로그아웃 또는 트레이의 종료로 중단합니다. PC가 꺼져 있으면 쪽지 감시는 동작하지 않습니다.
- **알림 옵션:** Solar 요약과 본문 포함을 각각 선택합니다. 설정은 `%LOCALAPPDATA%/SpacekijunDesk/desktop-preferences.json`에 저장하며 다음 쪽지부터 적용합니다. 기본값은 기존 동작과 같이 둘 다 켜짐입니다.
- **보관 기간:** 서버에서 매시 정각에 생성 후 한 달이 지난 `coolmessenger` 유형의 알림을 삭제합니다. 달력 기준 한 달이며 최대 한 시간 후 정리됩니다. 다른 알림과 쿨메신저 원본 쪽지·답장 큐는 이 정책의 대상이 아닙니다. 마이그레이션은 SPACEKIJUN 프로젝트의 `supabase/migrations/20260911031500_coolmessenger_notification_retention.sql`에 있습니다.

인증서 암호는 기존 DPAPI 저장소를 사용하며 웹 화면에 다시 전달하지 않습니다. 웹 화면에는 계정 토큰이나 DB 관리자 키를 전달하지 않습니다. 데스크 계정 연동과 NEIS·업무포털 인증서 로그인은 기존 브라우저 흐름을 사용합니다.

### 프로그램 안에서 스페이스기전 열기

`스페이스기전 열기`는 앱의 전용 WebView2 창에서 `https://spacekijun.lovable.app`을 직접 불러옵니다. 이미 열린 창이 있으면 재사용합니다. 웹사이트에는 로컬 Python API를 노출하지 않습니다.

SPACEKIJUN 프로젝트의 변경 사항을 해당 주소에 배포하면 실행 파일을 다시 만들 필요 없이 새로고침으로 반영됩니다. 소스 코드만 수정하고 배포하지 않은 변경 사항은 반영되지 않습니다. 전용 창의 `스페이스기전` 메뉴에서 새로고침·업무 홈 이동·데스크 설정 열기를 사용할 수 있습니다.

전용 창의 웹 로그인 상태는 `%LOCALAPPDATA%/SpacekijunDesk/webview-profile`에 유지합니다. 데스크 계정이 연결되어 있으면 스페이스기전·기전시트온의 전용 창에 별도 웹 세션을 발급해 자동 로그인합니다. 일반 브라우저로 직접 접속하는 Google 로그인은 유지됩니다. 전용 창을 닫아도 데스크의 자동 감시는 계속되고, 트레이에서 프로그램을 종료하면 전용 창도 함께 종료합니다.

### 스페이스기전 학생 (학생판)

학생이 쓰는 것만 담은 독입니다. `dist/SpacekijunStudent.exe`(약 23MB, 다시 만들기: `python -m PyInstaller --noconfirm --clean SpacekijunStudent.spec`) 또는 `스페이스기전-학생.bat`(`app/student.py`)으로 켭니다. 데스크 창은 없고 **독이 곧 프로그램**입니다.

| 독 아이콘 | 누르면 |

- **스티커 메모 창**에는 제목 표시줄이 없습니다. 위쪽 막대 가운데를 잡고 끌어 옮기고, X 로 닫고(메모는 남음), 오른쪽 아래 손잡이로 크기를 바꿉니다. 쓰는 동안은 글자 그대로, 다 쓰면 `# 제목`(`##`·`###`)은 크게, `- 목록`은 점으로, 웹 주소(`https://…`·`www.…`)는 누르면 기본 브라우저로 열리는 링크로 보입니다. 글자를 누르면 그 자리에서 다시 고칩니다.

### 클립보드 — 복사한 것을 모아 두고 다시 쓰기

컴퓨터 어디서든 **Ctrl+C**(오른쪽 클릭 → 복사 포함)로 복사한 **글·그림·파일**을 모아 둡니다(`core/clipboard_history.py`). 독의 `클립보드`를 누르면 독 위 패널에 새것부터 보이고, **누르면 다시 클립보드에 복사**되어 Ctrl+V 로 어디든 붙여 넣을 수 있습니다.

- 목록(글 포함)은 `%LOCALAPPDATA%/SpacekijunDesk/clipboard/history.dat` 에 **DPAPI 로 암호화**해 이 PC·이 계정만 읽을 수 있고, 그림은 같은 폴더에 PNG 로 둡니다.
- Windows 에도 클립보드 기록(Win+V)이 있습니다. 이 기능은 독에서 바로 보이고, 다시 켜도 남고, 찾기·더 많은 개수를 지원합니다.

#### 자동화 업무 — 업무용 스킬을 한 폴더에 깔아 두고 거기서 열기 (교사판 전용, 2026-10-22)

  - **'일하는 중' 표시 기준 (2026-10-26)**: 모든 출력이 아니라 에이전트가 **실제로 일한 출력**만 셉니다(`Session.quiet_for`). 창 제목·커서·색 같은 제어 문자만 있는 출력, 사람이 친 글자의 메아리, 창 크기·포커스가 바뀌어 다시 그리는 출력(입력·크기 바꾸기 뒤 0.5초, `ECHO_GAP`)은 빼고, Enter 뒤의 출력은 대답이라 셉니다. 마지막으로 일한 출력에서 2초(`agent_bridge.WORKING_GAP`) 안이면 '일하는 중'. 이 이름 바꾸기는 로컬 이름과 별개로 실패할 수 있고, 다시 시작하면 열 때의 이름으로 돌아갑니다. 설정 파일(`remoteControlAtStartup`)은 건드리지 않습니다 — 그건 이 프로그램 밖의 모든 Claude 세션까지 켭니다. 조건: claude.ai 구독 로그인(API 키·Bedrock·`ANTHROPIC_BASE_URL` 변경은 안 됨), Team/Enterprise 는 Owner 가 켜야 함. 조건이 안 맞아도 세션은 그대로 열리고 연결 실패 알림만 뜹니다. 옛 판이 인자를 모르면 터미널이 바로 꺼지므로 `claude --help` 에 `--remote-control` 이 있는지 먼저 봅니다(`agent.remote_supported`, 판이 바뀔 때까지 기억). 한글이 안 되는 코드페이지면 영문 이름(`Desk`)으로 바꿉니다.

### 캡처 — 잘라 담고, 파일처럼 끌어 쓰기

독의 `캡처`(또는 트레이 메뉴 `화면 캡처`)를 누르면 **Windows 캡처 화면**(Win+Shift+S 와 같은 것)이 뜹니다. 사각형·자유형·창·전체 화면 중 골라 자르면 그림이 PNG 파일로 `%LOCALAPPDATA%/SpacekijunDesk/captures`에 저장되고 **캡처 보관함** 창이 떠서 새 그림이 맨 앞에 내려앉습니다. 여러 번 찍으면 날짜별로 차곡차곡 쌓입니다(폴더처럼).

| 보관함에서 | 하는 일 |
|---|---|
| 끌어서 다른 프로그램에 놓기 | Windows **파일 끌기**로 넘깁니다 — 탐색기·메신저·메일·한글 등에 파일을 놓듯이. 원본은 보관함에 남습니다(복사) |
| 두 번 누르기 / Enter | 기본 프로그램(사진 앱 등)으로 엽니다 |
| 이름을 두 번 누르기 / F2 | 이름 바꾸기. 확장자는 그대로 두고, 같은 이름·Windows 금지 문자는 막습니다 |
| Delete | **휴지통**으로 옮깁니다(되살릴 수 있음) |
| Ctrl+C | 그림과 파일을 함께 복사 — 그림판·한글에는 그림으로, 탐색기에는 파일로 붙습니다 |
| Ctrl·Shift+누르기, Ctrl+A | 여러 개 고르기. 고른 것을 한꺼번에 끌기·복사·지우기 |
| 오른쪽 클릭 | 열기·복사·이름 바꾸기·파일 위치 열기·휴지통으로 옮기기 |

탐색기에서 이 폴더에 넣거나 지운 것도 몇 초 안에 보관함에 반영됩니다.

- 영역 고르기는 Windows 캡처 화면에 맡기고, 그 결과가 클립보드에 오면 받습니다(`core/capture.py`). Esc 로 닫으면 캡처 화면 창(`캡처 도구 오버레이`)이 사라지는 것을 보고 곧바로 취소로 봅니다. 그 창을 알아보지 못하는 Windows 에서는 2분까지 기다립니다.
- 끌기는 화면(JS)이 단추를 누른 채 움직이는 것을 보고 보관함 창의 UI 스레드에서 WinForms `DoDragDrop`(파일 목록)을 시작합니다. 웹 끌기(`DownloadURL`)는 메신저 등이 받지 못해 쓰지 않습니다.
- 캡처 화면이 닫히면 Windows 가 앞 창에 포커스를 돌려주며 그 창을 맨 위로 올립니다. 그래서 보관함은 캡처 화면이 다 닫힌 뒤에 띄웁니다.

### 에듀파인 바로보기 — 뷰어 없이 공문 분석 보기 (2026-11-12)

데스크로 연 K-에듀파인 탭(업무포털 링크로 연 탭도 2초 안에)의 문서 목록에서, SPACEKIJUN `official_doc` 에 있는 문서 제목 옆에 **«바로보기»** 단추를 붙입니다. 누르면 뷰어(WXSClient)를 기다리지 않고 오른쪽 패널로 AI 요약과 그 바로 밑에 **원문**(서버 PC 가 모아 DB `official_doc.body` 에 둔 본문 글, 접지 않고 전부), 그다음 성격·기한(D-day)·판정 근거·업무 후보·**담당**·처리 결정·붙임·비슷한 지난 공문을 봅니다. 담당은 데이터에 정해진 사람이 기본이다 — 처리 결정에서 정한 담당, 없으면 문서등록대장 결재권자(= 실제 접수 담당). AI 의 담당 후보는 데이터에 담당이 없을 때만 «담당 후보 (AI)»로 보여 준다(1.3.82). «확인할 것»(AI 의 질문)은 이 패널에서 뺐습니다(1.3.81). 원문이 아직 없는 공문(10/12 이후 424건 중 45건, 주로 막 들어온 것)은 «에듀파인에서 원문 열기»로 안내합니다. ↑↓ 로 같은 쪽의 다음 문서, Esc 로 닫기, «에듀파인에서 원문 열기»는 원래 제목 링크를 그대로 누릅니다. **보기 전용** — 에듀파인에 아무것도 쓰지 않습니다.

- 원문의 표: 서버 PC 수집기(odt-doc.js)가 표를 `| 칸 | 칸 |` 줄로 남긴다(10/31~) → 이어진 `|` 줄을 표로 그린다(`| --- |` 위는 머리줄). 일정: AI 판정의 `deadlines`(신청·제출 기한·행사일)를 AI 요약 카드 안에 날짜순·D-day 로(지난 것은 흐리게), 아래 «기한» 칸은 뺐다(1.3.85).
- **업무노트 열기**(1.3.86): 공문과 이어진 SPACEKIJUN 업무노트 페이지 — 판단함 최근 결정의 `work_id/task_id` + 업무·할 일의 `meta.fromOfficialDoc.doc_no` — 를 패널 «업무노트» 칸과 아래 «SPACEKIJUN에서 열기»로 연다. 하나면 바로, 여럿이면 모달에서 고른다. 할 일은 그 업무 쪽 `/work/o/work/<업무>?task=<할 일>`. 목록 단추에 «업무 n». 여는 일은 바인딩 `__deskKlefOpen` → `DesktopAPI._klef_open` 이 주소를 `klef_overlay.SPACE_PAGE`(업무노트 한 장·구매 신청 페이지)로 다시 확인하고 데스크의 스페이스기전 창(`_show_space`)에 연다.

### 어디서 열리나 — 두 갈래 (2026-09-15)

| 서비스 | 어디서 | 왜 |
|---|---|---|
| 나이스 · 전북 업무포털 · K-에듀파인 | **설치된 Edge** | 서로 링크로 오가고, 인쇄·내려받기 같은 창이 잦다 |
| 리로스쿨 · 전북 AIEP | **데스크 안 창** | 아이디·비밀번호 한 벌로 끝나고 다른 데로 넘어가지 않는다 |

인증서 셋을 Edge 로 되돌린 것은 2026-09-15 요청입니다. 하루 동안 다섯 전부를 데스크 안에서 열어 보았는데, 업무포털에서 나이스로 넘어가는 길이 진짜 브라우저라야 매끄러웠습니다.

`DesktopAPI.EDGE_TARGETS` 가 그 갈림길입니다. 일꾼 하나(`_serve_browser`)가 두 갈래를 함께 쥡니다 — Playwright 는 자기를 만든 스레드에서만 만질 수 있어서 도우미 일감까지 모두 여기서 돕니다. 브라우저는 **필요할 때 처음 한 번만** 띄웁니다. 리로스쿨만 쓰시는 PC 에서 Edge 가 괜히 뜨지 않습니다.

#### Edge 갈래

다섯이 아니라 셋이 한 프로필(`portal.SHARED_FOLDER`)을 함께 씁니다. 그 창에서 Edge 에 한 번 로그인하시면 셋 모두에 즐겨찾기·설정·확장이 적용됩니다. 서비스마다 창은 따로입니다 — 프로필 하나는 한 프로세스만 열 수 있어서, 창을 더 만드는 길은 크기를 준 `window.open` 뿐입니다(`_new_window`).

**업무포털에서 나이스로 넘어가는 길이 여기서 살아납니다.** 실측(2026-09-15): 업무포털에서 `나이스` 를 눌러 `jbe.neis.go.kr/jsp/main.jsp` 가 열렸고 로그인된 화면(로그아웃 타이머)이 그대로 보였습니다.

**Chrome 으로 열기 (테스트 기능, 2026-10-23).** 교사판 `연결 및 설정 > 인증서 자동 로그인 > 브라우저 (테스트)` 에서 Chrome 을 고르면 셋을 Chrome 으로 엽니다(`desktop-preferences.json` 의 `cert_browser`, `portal.BROWSERS`). 띄우고 붙는 방식은 Edge 와 같고 프로필만 `browser-chrome` 으로 나눕니다. Edge 에서 허용해 둔 로컬 네트워크 권한은 넘어가지 않으므로 **처음에 "로컬 네트워크 접근" 물음에 허용**을 눌러야 합니다. Chrome 이 없는 PC 에서는 고를 수 없고, 골라 둔 뒤 지워졌으면 Edge 로 엽니다. 바꾸면 이미 떠 있는 창에는 적용되지 않고 그 창을 닫은 뒤부터 적용됩니다. 검증: Chrome 155 로 띄우고 붙기까지 확인. 학교 망 밖이라 나이스 자동 로그인은 아직 Chrome 에서 확인하지 못했습니다.

**평소 쓰는 Edge 프로필은 쓰지 않습니다.** 이미 켜져 있으면 새 창이 그쪽으로 넘어가 자동화가 제어를 잃습니다. 2026-09-14 에 두 번 겪었고, 그때마다 `기존 브라우저 세션에서 열기` 로 끝났습니다.

##### 창은 누른 만큼만 뜹니다

🚨 여기서 두 가지가 겹쳐 **나이스 하나를 눌렀는데 창이 셋** 떴습니다 (2026-09-15 사용자 보고).

**하나, Edge 가 지난번 창을 되살립니다.** 아무것도 하지 않고 띄우기만 했는데 며칠 전 `klef.jbe.go.kr` 창이 먼저 떠 있었습니다. `portal.forget_last_session` 이 띄우기 **직전에** 프로필의 세션 기록(`Default/Sessions`)을 지우고 `restore_on_startup` 을 새 탭으로 못 박습니다. 둘 다 하는 이유는, 설정만 고치면 동기화된 설정이 덮을 수 있고 기록만 지우면 다음에 또 쌓이기 때문입니다. 브라우저가 떠 있는 동안에는 부르면 안 됩니다 — 그때는 Edge 가 그 파일들을 쥐고 있습니다.

**둘, 브라우저가 처음 주는 빈 창을 버려 두었습니다.** `_new_window` 가 그 빈 창을 먼저 씁니다. 새 창은 두 번째 서비스부터 만듭니다.

실측(2026-09-15): 나이스만 → **창 1개**, 나이스 + 업무포털 → **창 2개**.

#### 데스크 안 갈래

리로스쿨·AIEP 는 데스크 창입니다(`_open_service_window`). 서비스마다 창이 따로고, 같은 서비스를 다시 누르면 열려 있던 창을 앞으로 가져옵니다. 데스크를 끝내면 함께 닫힙니다.

도우미가 붙을 수 있는 것은 이 통로 덕분입니다.

```python
webview.settings['REMOTE_DEBUGGING_PORT'] = DEBUG_PORT   # desktop.py main()
...
pw.chromium.connect_over_cdp(f'http://127.0.0.1:{DEBUG_PORT}')   # DesktopAPI._connect
```

pywebview 가 이 값을 WebView2 에 그대로 넘겨 줍니다(`platforms/edgechromium.py`). 환경변수 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 로는 되지 않습니다. 포트는 `127.0.0.1` 에만 열리고 프로그램이 꺼지면 함께 닫힙니다. 창이 여럿이어도 통로는 하나입니다.

#### 빠뜨리기 쉬운 두 가지

**하나, 동기 API 는 우리가 부를 때만 알림을 처리합니다.** `browser.contexts` 는 그 자리에서 읽는 값이라 드나들지 않습니다. 되풀이해 읽기만 하면 **새 창이 생긴 것을 영영 모릅니다.** 이걸 빠뜨려 30초를 세다 "창을 찾지 못했습니다" 로 끝났습니다. `_pump`·`_still_there` 가 한 번 드나들며 소식을 받아 옵니다.

**둘, 일꾼은 데스크가 살아 있는 한 같이 삽니다.** 브라우저가 닫혔다고 일꾼을 끝내면, 다음 요청 때 새 스레드에서 Playwright 를 다시 켜야 합니다 — 그것이 `signal only works in main thread of the main interpreter` 로 실패합니다(2026-09-15 실측). 그래서 닫힌 쪽만 놓고 자리를 지킵니다. Edge 를 닫으면 그 셋만 풀어 주고 데스크 쪽은 그대로 둡니다.

#### 내려받기 — 두 갈래가 다릅니다

🚨 **Playwright 는 붙는 순간 내려받기를 가로챕니다.** `Browser.setDownloadBehavior` 를 `allowAndName` 으로 바꾸는데, 이것은 브라우저 **전체**에 걸립니다. 그러면 파일이 Playwright 임시 폴더에 `d6b39ae4-…` 같은 GUID 이름으로 떨어지고, 게다가 Playwright 는 곱게 끝날 때 그 폴더를 **지웁니다.** 선생님 눈에는 "이름이 이상하고 다운로드 폴더에 없다" 로 보입니다 (2026-09-15 보고). 9/14 에 받으신 81개가 그렇게 임시 폴더에 남아 있었습니다.

갈래마다 막는 방법이 다릅니다. 둘 다 실측으로 확인했습니다.

| 갈래 | 방법 | 결과 |
|---|---|---|
| 데스크 안 창 | `_free_downloads` — CDP 로 `behavior: 'default'` | `…\Downloads\출결자료.txt` |
| Edge | `portal.open_shared_edge` — Edge 를 **평소처럼 띄우고** `connect_over_cdp(no_defaults=True)` 로 붙는다 | `…\Downloads\출결자료.txt`, Edge 의 "파일 열기"·"폴더에 표시" 도 동작 |

🚨 **Edge 는 되돌리는 것으로는 안 됩니다.** Playwright 가 한 번이라도 `Browser.setDownloadBehavior` 를 보내면, 나중에 `default` 로 되돌려 파일이 제 자리에 떨어져도 Edge 다운로드 목록의 "파일 열기"·"폴더에 표시" 는 **아무 일도 하지 않습니다** (2026-10-12 사용자 보고·실측: 평소 Edge 는 되고 붙은 Edge 는 안 됨). `launch_persistent_context` 는 반드시 그 명령을 보내므로 쓰지 않습니다. `no_defaults=True` 로 붙으면 보내지 않습니다.

- Edge 는 `--remote-debugging-port=0` 으로 띄우고, Edge 가 고른 포트를 프로필의 `DevToolsActivePort` 에서 읽습니다. 127.0.0.1 에만 열립니다.
- 데스크가 끝나면 Edge 는 닫지 않고 연결만 놓습니다. 다음에 켜면 떠 있는 Edge 에 다시 붙습니다.
- ⚠️ 붙어 있는 동안 `edge://downloads`(Ctrl+J)를 연 적이 있으면, 그 탭을 닫아도 **다시 붙는 것이 멈춥니다.** 그때는 10초 뒤 "Edge 창을 모두 닫고 다시 눌러 주세요" 로 알립니다.

이름은 서버가 준 것이라 그대로 믿지 않습니다. `core/downloads.py` 가 폴더를 벗어나는 글자를 걷어 내고, 같은 이름이 있으면 브라우저처럼 `자료 (2).xlsx` 로 비켜 줍니다.

#### 페이지가 스스로 여는 창 (데스크 안 갈래)

pywebview 는 새 창 요청을 기본으로 **바깥 브라우저**에 넘깁니다(`OPEN_EXTERNAL_LINKS_IN_BROWSER`). 바깥은 프로필이 달라 **로그인이 끊긴 채** 뜹니다. `core/web_popup.py` 가 이 요청을 가로채 데스크 안 창으로 엽니다.

🚨 **단, 페이지가 돌려받은 창을 쓰는 요청은 가로채지 않습니다**(`wants_window`) — 빈 창(`window.open('', …)`)에 문서를 써 넣어 인쇄하는 출력 창, `blob:` 주소, 크기·위치를 준 작은 창(별까지 쌓기 미니 창). 데스크 창으로 돌리면 `window.open` 이 null 을 받아 스페이스기전이 "팝업이 차단되어 출력 창을 열지 못했습니다" 를 띄웠습니다(2026-10-12 보고). 이것들은 WebView2 가 제 팝업 창으로 엽니다 — 같은 프로필이라 로그인이 이어지고 인쇄도 됩니다.

**창을 하나라도 만들기 전에** 불러야 합니다. pywebview 는 창이 뜰 때 처리기를 *묶인 메서드*로 등록해서, 나중에 갈아 끼우면 이미 뜬 창은 옛 손을 그대로 쥡니다. 늦게 부르면 아무 일도 일어나지 않습니다.

Edge 갈래는 진짜 브라우저라 이런 손질이 필요 없습니다. 다만 **자동화가 여는 팝업은 다릅니다** — `page.evaluate` 로 부른 `window.open` 은 사용자 동작으로 치지 않아 크로미움 팝업 차단에 걸립니다. 점검 스크립트에서 링크를 누를 때는 진짜 클릭(`locator.click()`)을 써야 합니다.

#### 판정식은 몸통이 없는 화면도 견뎌야 합니다

화면이 넘어가는 찰나에는 `document.body` 가 잠깐 없습니다. 그때 `.innerText` 를 읽으면 판정식이 **예외로 끝나** `wait_for_function` 이 기다리기를 그만둡니다 — 다음 바퀴에 다시 보지 않고 로그인이 통째로 중단됩니다. 2026-09-15 에 업무포털이 `Cannot read properties of null` 로 멈췄습니다. 여섯 군데에 `(document.body ? document.body.innerText : '')` 를 넣었고, `test_portal` 이 몸통을 떼어 낸 화면에 모든 `_SIGNED_IN`·`_READY` 를 걸어 봅니다.

#### 로그인이 끝나면 손을 뗍니다

나이스만 계속 쥡니다 — 도우미 패널이 그 창에 붙어 있기 때문입니다. 나머지 넷은 로그인이 끝나는 즉시 놓아 줍니다. 닫혔는지 되묻지도 않습니다(`page.on('close')` 로 알림만 받습니다).

#### 저장된 것이 없으면

자동 로그인을 시도하지 않고 그 사이트만 엽니다(`_open_plain`). **어디서 여는지는 그 서비스가 평소 어디서 열리는지를 따릅니다** — 인증서 셋은 평소 쓰시는 브라우저로, 리로스쿨·AIEP 는 데스크 안 창으로. 아무것도 입력해 주지 않습니다.

구글 로그인(데스크 계정 연결)은 늘 **바깥 브라우저**를 씁니다. 구글이 프로그램 안 브라우저에서의 로그인을 막기 때문입니다.

### 리로스쿨 · 전북 AIEP 자동 로그인

이 둘만 **인증서를 쓰지 않습니다.** 아이디와 비밀번호로 들어갑니다. 그래서 설정 화면의 칸도 인증서와 따로 두었습니다.

| 서비스 | 아이디 | 로그인 주소 |
|---|---|---|
| 리로스쿨 | 학교 아이디 또는 통합 아이디(이메일) | `kijun.riroschool.kr` |
| 전북 AIEP | `@ai.jbedu.kr` 앞부분 | `ai-auth.jbedu.kr` |

설정에 아이디와 비밀번호를 저장하면 홈의 해당 버튼이 자동 로그인으로 바뀝니다.

**설정이 비어 있으면 막지 않고 그냥 그 사이트를 엽니다.** 나이스·업무포털·에듀파인·리로스쿨·AIEP 다섯 개 모두 같습니다. 자동 로그인은 덤이지 조건이 아니라, 저장하지 않아도 버튼은 그대로 쓸 수 있습니다. 활동 기록에는 무엇을 저장하면 자동으로 되는지 한 줄 남깁니다.

판단은 **자격증명 파일이 있는지가 아니라 그 서비스에 필요한 값이 들어 있는지**로 합니다.

| 서비스 | 있어야 자동 로그인 |
|---|---|
| 나이스 · 업무포털 · 에듀파인 | 아이디 + 인증서 암호 |
| 리로스쿨 | 리로스쿨 아이디 + 비밀번호 |
| 전북 AIEP | AIEP 아이디 + 비밀번호 |

인증서 사용자 이름은 인증서가 여러 장일 때 골라내는 용도라 없어도 로그인은 됩니다. 파일 존재만 보던 때에는 리로스쿨만 저장해 둔 PC 에서 나이스가 자동 로그인을 시도하다 실패했습니다.

2026-09-14 실측입니다. 빈 프로필에서 시작해 두 곳 모두 들어갔고, 다시 열면 로그인된 세션을 그대로 씁니다.

| 서비스 | 걸린 시간 | 도착 화면 |
|---|---|---|
| 리로스쿨 | 1.6초 | `kijun.riroschool.kr` · 권민결 교무부 |
| 전북 AIEP | 9.5초 | `ai.jbedu.kr/mainTchr.html` · 마이페이지·로그아웃 |

#### 여기서 걸린 함정 셋

**리로스쿨: `로그인` 단추가 네 개입니다.** 셋은 숨어 있는 재로그인·세션연장 팝업 것이고 보이는 진짜 단추는 하나뿐입니다. `.first` 로 고르면 숨은 것을 눌러 **아무 일도 일어나지 않습니다.** 보이는 것만 추립니다(`button:visible`).

**AIEP: 로그인 폼 주소로 바로 들어가면 안 됩니다.** 폼은 보이지만 제출하는 순간 `/idp/login/process/` 가 처리할 요청이 없어 무한 리디렉션에 빠집니다. 첫 화면에서 역할을 고르고 들어가야 통합 인증이 요청을 준비합니다. 그래서 사람이 하는 순서를 그대로 따라갑니다. 첫 화면 → 공지 닫기 → 교사 → 사용자 로그인 → 폼.

**AIEP: 값만 꽂으면 로그인이 붙지 않습니다.** 폼에 숨은 `email` 칸이 있고 화면 스크립트가 키 입력을 듣고 그것을 채웁니다. `fill()` 로 넣으면 그 칸이 빈 채로 넘어가 서버가 조용히 첫 화면으로 되돌려보냅니다. 사람처럼 한 글자씩 칩니다. 폼이 두 판이라 칸 이름도 둘 다 받습니다(`#pw, #password`).

아이디 칸은 `@ai.jbedu.kr` 앞부분만 받으므로, 전체 주소를 저장해 두어도 꼬리를 떼고 넣습니다.

AIEP 에는 인증서(정부 통합로그인) 길도 있습니다. 그 길을 쓰면 Edge 로컬 네트워크 정책에 AIEP 주소도 넣어야 합니다. AIEP 공지사항이 같은 내용을 안내하고 있습니다.

비밀번호는 인증서 암호와 같은 곳에 같은 방식으로 보관합니다. 윈도우 DPAPI로 이 PC의 이 계정에서만 풀리게 암호화하므로 파일만 복사해 가면 열지 못합니다. 저장된 비밀번호는 화면으로 돌려보내지 않으며, 비밀번호 칸을 비우고 저장하면 기존 비밀번호를 유지합니다.

둘 다 데스크 안 창으로 열리며 나이스 창을 켜 둔 채로도 충돌하지 않습니다. 인증서를 쓰지 않으니 아래의 Edge 로컬 네트워크 정책은 리로스쿨에 필요 없습니다.

#### 연결 해제

설정의 각 칸에 **연결 해제** 단추가 있습니다. 누르면 한 번 묻고, 그 서비스의 저장된 아이디와 비밀번호를 이 PC에서 지웁니다. 다른 서비스 것은 그대로 둡니다. 남은 것이 없으면 자격증명 파일 자체를 없앱니다.

리로스쿨과 AIEP는 **브라우저에 남은 로그인까지** 지웁니다. 정보만 지우고 브라우저가 로그인된 채면 연결을 끊었다고 할 수 없기 때문입니다. 그 창이 열려 있어 못 지우면 그렇다고 알려 줍니다.

인증서 쪽 브라우저 프로필은 건드리지 않습니다. 거기에는 로컬 네트워크 접근 허용이 들어 있어서, 지우면 "이 장치에서 다른 앱 및 서비스에 액세스" 물음을 다시 받게 됩니다.

명령줄로 저장하고 확인할 수도 있습니다. 비밀번호는 입력하는 동안 화면에 찍히지 않습니다.

```powershell
python scripts/save-login-credentials.py riro    # 저장 (--show 로 확인, --clear 로 삭제)
python scripts/save-login-credentials.py aiep
python scripts/check-live-login.py riro          # 실제로 로그인해 본다 (--fresh 로 빈 프로필)
python scripts/check-live-login.py aiep

python scripts/check-live-portals.py neis aiep      # 데스크 안 창으로 열리는지
```

`check-live-portals.py` 는 데스크를 진짜로 띄우고, 요청한 서비스가 **데스크 안 창**으로 열려 각각 로그인이 끝나는지 봅니다. 나이스를 포함하면 도우미에 말도 한 번 걸어 봅니다. 데스크를 띄워야 하는 이유는 창이 하나도 없으면 WebView2 가 디버깅 통로를 열지 않아 도우미가 붙을 자리가 없기 때문입니다. 포트가 겹치므로 **데스크를 먼저 닫고** 돌리십시오.

### 자동 로그인 · 배포 전에 반드시 넣을 Edge 정책

**증상.** 배포한 PC 에서 자동 로그인이 느리거나 멈춥니다. 처음 실행할 때 "이 장치에서 다른 앱 및 서비스에 액세스" 물음이 뜹니다.

**원인.** Edge 가 최근 버전부터 로컬 네트워크 접근을 권한으로 막습니다. 인증서 프로그램(KSignCASE)은 컴퓨터 안 `127.0.0.1:8443` 에 있어서, 웹 페이지가 거기에 접속해야 인증서 목록을 읽습니다. 막히면 페이지가 로딩 덮개(`.isloading-overlay`)를 **영영 걷지 않습니다.** 덮개 아래로 들어간 클릭은 조용히 사라집니다.

2026-09-14 실측입니다. 승인 이력이 없는 새 프로필에서 같은 페이지를 45초 동안 지켜봤습니다.

| 조건 | 덮개가 떠 있던 시간 | 실제 로그인 |
|---|---|---|
| 정책 없음 | 45.0초 / 45초 | 실패 |
| 정책 있음 | 0.5초 / 45초 | 성공, 4.8초 |

**조치.** Edge 정책 하나면 됩니다. 물음 자체가 사라집니다.

```
HKLM\SOFTWARE\Policies\Microsoft\Edge\LoopbackNetworkAllowedForUrls
   1 = https://jbe.neis.go.kr
   2 = https://jbe.eduptl.kr
   3 = https://klef.jbe.go.kr
```

전북교육청은 이미 같은 방식을 씁니다. `LocalNetworkAccessAllowedForUrls` 에 SharePoint 주소가 들어 있습니다. 같은 통로로 위 세 주소를 요청하면 됩니다.

**정책을 못 넣는 PC.** 사용자가 물음에 **허용**을 누르면 그 프로필에 저장됩니다. 다만 **거절하거나 창을 몇 번 닫으면 Edge 가 묻지 않고 영구 차단**합니다. 그 뒤로는 사이트 권한에서 직접 되돌려야 합니다. 처음 쓰는 선생님께는 이 물음을 미리 안내해 주십시오.

### 자동 로그인 대기 시간

NEIS의 고정 4초·10초, 업무포털의 고정 5초·9초 대기를 제거하고 화면의 버튼과 로그인 성공 요소가 나타나는 즉시 진행합니다. 보안프로그램 설치 안내 링크는 로딩으로 취급하지 않습니다. 실제 로딩 문구와 가려진 버튼은 계속 기다립니다. 단계별 경과 시간을 활동 기록에 남기며 바로가기 버튼에도 진행 단계를 표시합니다. 서버 응답과 보안프로그램 준비 시간은 별도로 필요합니다.

로딩 덮개가 걷힐 때까지 최대 45초 기다리고, **안 걷히면 밀고 나가지 않습니다.** 대신 무엇이 막고 있는지와 위 정책을 답으로 알려 줍니다. 예전에는 15초만 기다린 뒤 결과를 보지 않고 눌렀고, 그 클릭이 사라진 채 2분 넘게 끌다가 "인증서 위젯이 뜨지 않았습니다"라는 엉뚱한 메시지로 끝났습니다. 인증서 창이 한 번에 안 뜨면 한 번 더 눌러 봅니다. 느린 PC 에서는 덮개가 막 걷힌 직후 앱이 클릭을 못 받는 때가 있습니다.

로컬 화면을 사용하는 `python -m unittest discover -s app -p 'test_*.py' -v`로 준비 상태·이미 로그인된 세션·에듀파인 아이디 입력 흐름을 검증할 수 있습니다. 실제 인증서 입력·로그인 검증과는 별개입니다.

Windows 자동 실행은 설정에서 선택하며 교사판은 기본 꺼짐입니다(학생판은 기본 켜짐). 현재 사용자 HKCU Run의 SpacekijunDesk 값으로 등록하고, --autostart 실행은 트레이에서 시작합니다. 다른 실행 파일로 교체하거나 이동한 뒤 한 번 실행하면 기존 등록 경로를 갱신합니다. 쿨메신저 자동 실행은 별도 설정입니다.

쿨메신저 연결 준비는 데스크의 연결 및 설정 → 쿨메신저 연결에서 수행합니다. 별도 BAT 없이 설치 경로를 찾아 필요한 연동 옵션으로 실행합니다. 실행 중인 클라이언트의 재시작은 작성 중인 내용을 저장하라는 안내에 동의한 경우에만 수행합니다. 설치 및 쿨메신저 계정 로그인은 별도입니다.

### SPACEKIJUN 홈 대시보드

업무 홈에 오늘 수업·일정, 이번 주 남은 일정·업무 마감, 미완료 나의 업무, 현재 게시 중인 학교 공지(최근 5건), 최근 알림(5건)을 표시합니다. 기존에 연결한 SPACEKIJUN 사용자 세션으로 조회하며, 홈을 보는 동안 1분마다 갱신하고(키보드·마우스를 10분 넘게 놓으면 쉬었다가 돌아오면 바로 갱신 — 미리 받아 두기도 같다, `desktop.py` `AWAY_AFTER`), 새로고침 버튼으로 즉시 확인할 수 있습니다. 공지는 눌러 본문을 펼치고, 각 카드의 전체 보기로 프로그램 안의 웹 상세 페이지를 엽니다. 웹 전용 창의 로그인은 데스크 연동 계정과 별도입니다.

조회 실패는 카드에 표시하고, 계정 변경·로그아웃 시 이전 내용을 지웁니다. 대시보드 데이터는 디스크에 저장하지 않습니다. 조회 규칙은 SPACEKIJUN의 시간표 학기 설정, 담당자 이름, 업무 완료 우선순위, 다중 마감, 공지 게시 기간을 참고했습니다. 웹의 결재·서명·좌석·담임 현황 등 추가 기능은 스페이스기전 열기로 이용합니다.

검증: `python -m unittest discover -s app -p 'test_*.py' -v`, `node scripts/test-dashboard.js`. 실제 연동 계정으로 다섯 영역 조회를 확인했습니다.

홈의 마지막 버튼 순서는 리로스쿨 → 기전시트온 → 스페이스기전입니다. 리로스쿨은 기본 브라우저로, 기전시트온은 프로그램 안의 전용 창으로 열립니다.

### 데스크 통합 로그인

설정에서 SPACEKIJUN 계정을 연결한 뒤 스페이스기전 또는 기전시트온을 열면 같은 사용자로 로그인합니다. 이미 열린 전용 창도 데스크 로그인 완료 시 연결합니다. 연결이 실패하거나 데스크 계정이 없으면 사이트의 기존 로그인 화면을 이용할 수 있습니다. 개별 사이트의 Google OAuth 구현은 수정하지 않았으며, 일반 브라우저의 세션은 변경하지 않습니다.

`core/web_login.py`는 고정된 두 HTTPS origin만 허용합니다. 원격 페이지에는 Python API를 노출하지 않으며, 토큰을 URL·활동 기록에 담지 않습니다. 서버 `desktop-session` 함수는 호출자 JWT를 서버에서 확인하고 본인의 별도 세션만 발급합니다. 관리자 키는 서버 환경에만 있으며 배포 EXE에는 포함되지 않습니다. MFA 계정은 자동 발급을 거절하고 기존 웹 로그인으로 안내합니다. 데스크 로그아웃은 데스크가 발급한 해당 전용 창의 세션만 로컬 범위로 해제합니다. 사이트에서 별도로 실행하는 로그아웃 정책은 각 사이트의 기존 정책을 따릅니다.

기존 JS 클라이언트의 Supabase 저장 형식과 시작 시 세션 복원 동작을 이용합니다. 사이트가 인증 저장 키/스토리지/초기화 방식을 바꾸면 데스크 연결 코드를 함께 갱신해야 합니다. Seaton의 `auth-storage` 프로필 캐시는 계정 연결 때 제거하여 이전 사용자 정보가 남지 않게 합니다.

세션을 넣은 뒤에는 **열려던 화면**(독에서 고른 `/planner` 등, 없으면 창이 보던 화면)을 다시 엽니다 — 다른 사이트이거나 로그인 화면(`/auth`)이면 첫 화면(`landing`). 예전에는 늘 첫 화면을 열어, 웹 세션이 끝나 가던 때(약 1시간마다 한 번) 고른 기능 대신 스페이스기전 홈이 열렸습니다(2026-10-14 사용자 보고, 교사판 1.3.10 · 학생판 1.0.5 에서 고침).

검증: `scripts/test-desktop-session.mjs`, `app/test_web_login.py`, `scripts/check-live-web-login.py`, `scripts/check-live-webview-login.py`. Live 검증은 별도 임시 프로필을 사용하며 새로 발급한 테스트 웹 세션만 로컬 로그아웃합니다.
