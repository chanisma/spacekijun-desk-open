# 리로스쿨 알림 문자 발송

최종 검증: 2026-10-22 — 샘플고등학교 교사 계정(`kijun.riroschool.kr`), Windows 11, Edge 155, Node 22.

> ⚠️ **아래 값은 고정값이 아니다.** 메뉴 이름·주소(`/sms.php?db=&action=send_form`)·화면 요소 id(`#msg_id` `#btn_sms` `members[]` `to_parent1` …)·함수 이름(`smsSubmit` 등)·내역 표 열은 리로스쿨 개편으로 바뀔 수 있다.
> 어느 날 갑자기 "화면 스크립트 오류"나 "수신자 선택이 맞지 않습니다"가 나오면 화면이 바뀐 것이다 — 추측해서 고치지 말고 화면 구조를 다시 읽어 맞춘다('화면 구조 메모').

## 🚨 먼저 알아둘 것 — 문자는 회수할 수 없고 비용이 든다

- 보낸 문자는 **취소할 수 없다.** 학부모·학생에게 실제로 도착하고 **학교 잔여 건수**와 **월별 허용 건수**를 쓴다(단문 1건, 장문 3건 차감).
- 그래서 이 스킬은 **미리보기(`preview`) → 사용자 승인 → 발송(`send`)** 순서만 허용한다. 미리보기는 아무것도 보내지 않는다.
- 학생·학부모 개인정보를 다룬다. 출력은 이름을 가려서(`홍○○`) 보여 주고, 기록 파일에는 수신자 id 만 남긴다.

## 무엇을 하고, 무엇을 안 하는가

| 한다 | 안 한다 (아직) |
|---|---|
| 학급·이름·id 로 수신자 찾기 (`find`) | **예약 발송** — 즉시 발송만. 예약이 켜져 있으면 발송을 거부한다 |
| 발송 전 **미리보기**: 받는 사람 수, 앱/단문/장문 건수, 차감 건수, 잔여 | 번호 **직접 입력** 발송 (주소록 회원에게만) |
| 승인된 미리보기와 **같은 것만** 발송 (`send`) | 사진 첨부, 메일머지 문자, 출결·상벌 문자 메뉴, 그룹 관리 |
| 로그인(저장된 계정으로 자동, 한 번만 시도), 발송 가능 건수 확인 (`status`) | 문자 본문을 대신 정해 주기 — 본문은 사용자가 정하고 승인한다 |
| 보낸 내역·예약 내역 읽기 (`history`) | 스팸·광고성 대량 발송 |

## 파일 구성

| 파일 | 역할 |
|---|---|
| `riro-sms.mjs` | **본체.** Edge 를 직접 조종(CDP)해 로그인·조회·미리보기·발송·내역. 의존성 없음 |
| `credentials.ps1` | 리로스쿨 계정 — DPAPI 로 암호화해 보관하거나, **스페이스기전 데스크에 저장된 계정을 읽기만** 한다 |
| `style.ps1` · `message-style.template.md` | 문자 **문체 프로필** (첫 사용 인터뷰 결과 저장·조회) |
| `skill.json` | 스페이스기전 데스크가 읽는 제목·필요 프로그램·민감 표시 |

자료 위치: `%LOCALAPPDATA%\RiroSms\` — `config.json`(학교 주소), `previews\`(미리보기 기록), `profile\`(Edge 전용 프로필), `message-style.md`(문체), 직접 저장한 계정. 스킬 폴더는 건드리지 않는다.

## 사전 조건

1. Windows + **Microsoft Edge** (설치돼 있다 — 데스크도 쓴다) + **Node.js 22 이상**
2. 리로스쿨 **교사 계정**(메뉴 `알림 > 문자 발송` 권한). 승인된 사람만 쓸 수 있다.
3. **학교 주소** 한 번 저장: `node riro-sms.mjs config --base https://학교.riroschool.kr`
   (`*.riroschool.kr` 가 아니면 거부한다 — 아이디·비밀번호를 넣는 곳이라 엉뚱한 주소로 새는 것을 막는다)
4. **계정** — 둘 중 하나:
   - 스페이스기전 데스크(교사판)에서 리로스쿨 자동 로그인 계정을 저장해 뒀다면 **그대로 쓴다**(읽기만, 다른 값은 쓰지 않음).
   - 아니면 사용자가 **본인 터미널에서** `powershell -File credentials.ps1 save` 로 저장한다. (비밀번호를 에이전트 대화창에 쓰지 말 것)
   - 확인: `powershell -File credentials.ps1 status` (아이디만 보여 준다)

## 작업 순서 (에이전트가 따를 것)

1. **문체 프로필 확인** — `powershell -File style.ps1 exists`. `no` 면 아래 '처음 쓸 때' 인터뷰부터. `yes` 면 `style.ps1 show` 를 읽고 그 문체로 쓴다.
2. **상태 확인** — `node riro-sms.mjs status` (로그인 성공, 발송 가능 건수). 학교 주소가 없으면 `config` 부터.
3. **수신자 확정** — `find` 로 실제 대상을 확인한다. **동명이인이면 멈추고 사용자에게 고르게 한다.**
   ```
   node riro-sms.mjs find --name 홍길동                 # 이름 (동명이인은 모두 나온다)
   node riro-sms.mjs find --class 3-8                   # 3학년 8반 전체 (학급 라벨은 '308학급')
   ```
4. **초안 작성** — 문체 프로필대로. 가능하면 **90byte(한글 약 45자) 이하 단문**으로. 치환 변수는 `{성명}` 만 가능.
5. **미리보기 → 사용자 확인** — 아래 명령의 출력을 **그대로** 사용자에게 보여 주고 승인을 받는다('발송 전 확인 게이트').
   ```
   node riro-sms.mjs preview --class 3-8 --to mother,father --message "…"
   node riro-sms.mjs preview --name 홍길동 --name-class 3-8 --to student --message "…"
   node riro-sms.mjs preview --member 26-30801,26-30802 --to mother --message-file 문자.txt
   ```
6. **승인 뒤에만 발송** — 미리보기가 알려 준 id 로:
   ```
   node riro-sms.mjs send --preview-id <id> --confirmed
   ```
7. **결과 보고** — 차감 건수, 남은 발송 가능 건수, 발송 내역 변화를 사용자에게 알린다. 앱 사용자는 앱으로 가고 차감되지 않는다(미리보기의 `앱 N건`).

### 옵션

| 옵션 | 뜻 |
|---|---|
| `--to student,mother,father,teacher` | **필수.** 누구에게 보낼지 (학생 본인 / 어머니 / 아버지 / 선생님). 어머니 폰이 없으면 아버지에게 간다고 화면이 안내한다 |
| `--type appsms\|allsms\|app\|sms` | 앱 또는 문자(기본) / 모두 문자 / 앱만 / 문자만(앱 사용자 제외) |
| `--sender school\|phone` | 발신 구분. 생략하면 화면의 기본값(보통 학교) |
| `--max-recipients N` | 수신자 상한(기본 50명). 넘으면 거부 — 정말 필요하면 **사용자 승인 후** `--allow-large` |
| `--reveal` | 출력에서 이름·번호를 가리지 않는다 (기본은 가림) |
| `--json` | 기계가 읽는 출력 |
| `--headed` | Edge 창을 보이게 (문제 확인용) |

## 처음 쓸 때 — 문체 인터뷰

`style.ps1 exists` 가 `no` 일 때만 한다(사용자당 1회). 사람마다 문자 문체가 다르므로, 초안을 쓰기 전에 **어떤 말투·구조로 쓸지 먼저 묻고 그 지식을 남긴다.**
질문 도구가 있으면 쓰고 없으면 대화로 묻는다. 한 번에 2~4개씩, 선택지와 짧은 예시를 같이 보여 준다.

| 묶음 | 물어볼 것 |
|---|---|
| 말투 | 존댓말 정도(합쇼체/해요체) · 이모티콘·기호 · 문장 길이 |
| 말머리·서명 | 말머리(`[학교명]`) · 시작·맺음 문구 · 서명(`○학년 ○반 담임`) · 호칭(`학부모님`/`{성명} 학생`) |
| 구조·길이 | 순서(요지 → 일시·장소 → 요청 → 맺음) · **단문(90byte) 우선인지 장문 허용인지** · 날짜 표기 |
| 보조 | 수신자별 차이(학부모·학생·교사) · **쓰지 않을 것**(민감정보 등) · 확인 생략 허용 범위(기본: 없음) |

- **저장**: `style.ps1 init` 으로 양식을 만들고 `style.ps1 path` 위치의 파일을 인터뷰 결과로 채운 뒤 사용자에게 보여 확인받는다.
- **저장하지 않는 것**: 학생·학부모 이름, 전화번호, 실제로 보낸 문자 본문. 규칙과 일반화한 예시 문장만 남긴다.
- **이후 교정**: 사용자가 초안을 고쳐 달라고 하면 고쳐 쓰고 `교정 이력` 에 한 줄 남긴다. 같은 지적이 반복되면 규칙에 반영할지 묻는다.

## 발송 전 확인 게이트 (필수)

**모든 문자는 미리보기를 보여 주고 승인을 받은 뒤에만 발송한다.** 수신자가 1명이어도, 짧아도 마찬가지다(프로필 `6. 발송 전 확인 규칙` 에 사용자가 직접 허용한 예외가 있을 때만 그 범위를 생략).

사용자에게 이것을 보여 준다:

| 항목 | 내용 |
|---|---|
| 받는 사람 | 학급·인원 (예: 3-8 24명) — 동명이인이 있었으면 어떻게 골랐는지 |
| 수신 구분·유형 | 어머니+아버지, 앱 또는 문자 … |
| **본문 전문** | 문자 그대로 (치환 변수 포함) |
| **건수** | 총 선택 대상, 앱 N건 / 단문 N건 / 장문 N건, **차감 N건**, 남은 발송 가능 건수 |

- 승인은 **"보내", "진행", "OK"** 처럼 분명한 말일 때만 인정한다. 질문·수정 요청·모호한 답은 승인이 아니다 — 고친 새 미리보기를 다시 보여 준다.
- **승인받은 미리보기와 같은 것만** 발송한다. 본문이나 수신자를 바꾸면 새 `preview` 가 필요하다(`send` 가 다른 내용은 못 보낸다).
- 건수가 클 때(수십 명 이상, 차감이 월별 허용에 근접)는 사용자에게 한 번 더 상기시킨다.
- 에이전트의 권한 설정("승인 없이 실행" 등)과 무관하게 이 게이트는 지킨다.

### 스크립트가 강제하는 것

- `preview` 는 리로스쿨 화면이 하는 "예상 발송 건수 확인 → 발송하시겠습니까?" 까지 가서 **취소**한다. 실제 발송 요청(`POST /sms.php`)은 **네트워크 단에서 차단**한다(`selftest` 로 확인 가능). 미리보기는 비밀번호를 쓰지 않고 가짜 값으로 화면을 통과한다.
- `send` 는 `--confirmed` 와 미리보기 id 가 있어야 하고, 기록이 **30분 안**이며 **아직 쓰지 않은 것**이어야 한다. 화면이 계산한 건수가 미리보기와 **같을 때만** 승인한다(다르면 취소). 승인과 동시에 기록을 '사용됨'으로 표시해 **같은 문자가 두 번 나가지 않는다.**
- 로그인은 **한 번만** 시도한다. 틀리면 멈춘다(리로스쿨은 5번 틀리면 계정을 잠근다).

## 한도·비용

- **단문(≤90byte) 1건, 장문(LMS) 3건 차감.**
- 🚨 **기본 유형 `appsms`(앱 또는 문자)는 앱에 로그인한 사람에게는 문자(SMS)가 아니라 앱 알림으로 간다 — 차감 0건.** (2026-10-22 실측: 학생 5명 전원이 앱 로그인 상태라 `실제 발송: 앱 5건 (총 0건 차감)` 이었다.)
  **문체 프로필(`3. 구조 · 길이` 의 `발송 유형`)에 사용자가 기본 유형을 정해 뒀으면 그것을 따른다.** 정해 둔 것이 없을 때:
  사용자가 "문자로 보내 달라"고 했는데 `appsms` 로 보내면 **문자가 가지 않는다.** 미리보기에서 `앱 N건` 이 나오면 사용자에게 알리고, 실제 문자를 원하면 `--type allsms` (장문은 1명당 3건 차감) 로 다시 미리보기 한다.
- 두 한도가 모두 남아 있어야 한다: **월별 허용**(개인, 이 계정은 200건)과 **학교 잔여**. 학교 잔여가 없으면 월별 허용이 있어도 못 보낸다.
- 같은 번호·같은 내용은 중복 제외된다(미리보기의 `중복 제외`).

## 화면 구조 메모 (유지보수용)

| 용도 | 주소 | 비고 |
|---|---|---|
| 문자 발송 | `/sms.php?db=&action=send_form` | `알림 > 문자 발송*` |
| 발송 내역 | `…action=history_all` | 열: 순번·유형·수신번호·이름(학번)·등급·발신인·날짜·유형·발송결과·재사용, 최근 6개월 |
| 예약 발송 내역 | `…action=history_reserve` | |
| (참고) 메일머지 / 출결 / 상벌 | `…action=merge` `abs` `record` | 이 스킬은 쓰지 않음 |

- **발송 흐름**: `#btn_sms` 클릭 → 대상·메시지 검사 → `POST /sms.php?header=sms_check_cnt`(건수 계산) → `smsCheck()` → 브라우저 `confirm("· 총 선택 대상: N건 … ▶ 실제 발송: 앱 a / 단문 s / 장문 l (총 T건 차감) … 발송하시겠습니까?")` → 승인 시 `smsSubmit()` 이 `POST /sms.php`(로그인 비밀번호 `admin_pass` 포함) → `발송 결과` 팝업(`.confirm_popup`).
  우리는 `window.confirm`·`alert` 를 덮어써서 문구를 읽고, 미리보기에서는 늘 취소, 발송에서는 건수가 같을 때만 승인한다.
- **수신자**: 학교 전체(2026-10-22 기준 709명)가 처음부터 화면에 올라와 있다. `input[name="members[]"]` 의 `value` 가 id(예: `26-30801`, `data` 의 첫 글자 `S`=학생 `T`=교사), `data-name` 이 이름. 학급은 `#tree-cl308`(라벨 `308학급` = 3학년 8반), 교사는 `비담임`·`1학년 담임`… 그룹.
  학년 탭(`li.gr_list`)은 화면 필터일 뿐이라 누르지 않는다. 우리는 체크박스를 값으로 직접 체크하고 `select_member()` 로 `sms_member` 를 채운다.
- **수신 구분**: `to_student`(학생 본인) · `to_parent2`(**어머니**) · `to_parent1`(**아버지**) · `to_teacher` — 번호가 반대로 붙어 있다. **발송 유형**: `#plus`(앱 또는 문자) `#allsms` `#app` `#sms`. **즉시/예약**: `#atonce`/`#reserve`. **발신**: `#sch`(학교)·`#ph`(휴대폰).

## 함정 (전부 실제로 겪음)

1. **메뉴가 접이식이라 항목이 숨겨져(0×0) 클릭이 안 된다.** 메뉴를 누르지 말고 **주소로 바로 들어간다**(`menuAction('/sms.php?…')` 의 주소).
2. **`로그인` 이 들어간 단추가 여러 개고 숨은 것이 섞여 있다**(재로그인·세션연장 팝업). 보이는 것만 누른다(`getClientRects().length`).
3. **발송 때 로그인 비밀번호를 한 번 더 요구한다**(`admin_pass`). 미리보기는 이것 없이 가짜 값으로 통과하고, 실제 발송에만 저장된 비밀번호를 쓴다.
4. **`confirm()` 은 진짜 대화상자다.** 가로채지 않으면 자동화가 멈춘다. 그래서 페이지 안에서 덮어쓰고, 혹시 진짜 대화상자가 뜨면 방어선으로 무조건 취소하게 해 뒀다(CDP — 이 방어선이 실제로 동작하는 경우는 만나지 못했다).
5. **`to_parent1` = 아버지, `to_parent2` = 어머니** (이름과 반대). 미리보기 출력은 한글 라벨로 보여 준다.
6. **어머니 폰이 없으면 아버지에게 간다**(화면 안내). 건수가 `대상` 보다 적을 수 있다 — 화면이 계산한 값이 정답이다.
7. **값만 넣지 않고 이벤트를 같이 보낸다.** 화면이 바이트 수·단문/장문 표시를 입력 이벤트로 갱신하는 것으로 보여 `input`/`keyup` 이벤트와 `cntByte()` 를 함께 부른다(값만 넣는 방식은 시험하지 않았다).
8. **내역 화면에 메시지 본문 열이 없다.** 확인은 날짜·수신자·발송결과와 건수 변화로 한다. 열: 순번·유형(알림)·수신번호·이름(학번)·등급·발신인·날짜·유형(단문/장문)·발송결과(성공)·재사용.
   **발송 직후에는 반영이 늦다**(몇 초) — 0건이면 잠시 뒤 `history` 로 다시 본다. 발송 결과 팝업과 **발송 가능 건수 차감**이 더 빠른 증거다.
9. **한 사람이 여러 그룹에 있으면 같은 id 의 체크박스가 여러 개다**(예: 학급 + `동아리 기장`). 전부 체크하면 `sms_member` 에 중복으로 들어가 "수신자 선택이 맞지 않습니다 (요청 2명, 선택 3명)" 로 멈췄다(2026-10-23). 지금은 id 당 첫 체크박스 하나만 체크한다. `find`·미리보기 목록에는 그룹마다 한 줄씩 나오지만 같은 사람이다.
10. **`{성명}` 은 성까지 들어간 전체 이름이다.** "○○아/야"처럼 이름 + 호격조사로 부르려면 `{성명}` 을 쓸 수 없으니, 학생마다 따로 미리보기·발송한다.
11. **Edge 는 전용 프로필(`%LOCALAPPDATA%\RiroSms\profile`)로 띄운다.** 사용자의 평소 Edge 프로필에는 원격 디버깅이 막혀 있다(136+). 동시에 두 번 실행하지 못하게 잠금 파일을 둔다.

## Claude Code · Codex 에서 쓰기

두 에이전트가 같은 `SKILL.md` 형식을 읽는다. 위치만 다르다 — Claude Code `.claude/skills/`, Codex `.agents/skills/`(사용자 전체는 `~\.agents\skills\`).

### 🚨 Codex 는 샌드박스 밖에서 실행해야 한다

이 스킬은 **Edge 를 띄우고, 외부 사이트(`*.riroschool.kr`)에 접속하고, 사용자 폴더의 계정 파일을 읽는다.** 2026-10-22 시험(codex-cli 0.163.0):

| 환경 | 결과 |
|---|---|
| 샌드박스 안 (`-s workspace-write`) | `node riro-sms.mjs status` 가 **`EPERM: operation not permitted, lstat 'C:\Users\User'`** 로 시작도 못 한다 |
| 샌드박스 없음 (`-s danger-full-access`) | `status` 성공 — 로그인, 발송 가능 건수 조회 |

→ Codex 는 `-s danger-full-access` 로 열거나, 승인을 받아 샌드박스 밖에서 실행한다. Claude Code 는 일반 권한 확인만 있으면 된다.
**샌드박스를 풀어도 위의 발송 확인 게이트는 그대로 지킨다** — 에이전트가 권한을 풀었다고 승인을 건너뛰지 않는다.

## 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| `학교 리로스쿨 주소가 없습니다` | 처음 쓴다 | `node riro-sms.mjs config --base https://학교.riroschool.kr` |
| `저장된 리로스쿨 계정이 없습니다` | 계정 없음 | 데스크에 계정 저장, 또는 사용자가 `credentials.ps1 save` |
| `로그인이 끝나지 않았습니다 … 다시 시도하지 않았습니다` | 아이디·비밀번호 불일치 | **재시도하지 말고** 사용자가 리로스쿨에서 직접 로그인해 확인하고 저장된 계정을 고친다 (5회 오류 시 잠김) |
| `다른 riro-sms 가 실행 중입니다` | 동시 실행 | 끝난 뒤 다시. 비정상 종료 흔적이면 `%LOCALAPPDATA%\RiroSms\run.lock` 삭제 |

| `수신자가 N명으로 한도를 넘습니다` | 상한 50명 | 필요하면 사용자 승인 후 `--allow-large` |
| `리로스쿨이 거부했습니다: …` | 화면의 검사에 걸림 (잔여 부족, 발송 가능한 대상 없음 등) | 메시지대로 조치. 미리보기라 아무것도 보내지 않았다 |
| `건수가 미리보기와 달라 발송하지 않았습니다` | 그사이 수신자·번호·잔여가 바뀜 | 다시 `preview` 하고 사용자에게 확인받는다 |
| `이 미리보기는 이미 발송에 썼습니다` | 중복 발송 방지 | 같은 문자를 또 보내야 하면 `preview` 부터 다시 |
| `발송이 완료되지 않았습니다: …` (비밀번호 등) | 서버가 거부 | 기록은 '사용됨'이므로 `history` 로 실제 발송 여부를 먼저 확인한 뒤 필요하면 새 `preview` |
| `화면 스크립트 오류` / `수신자 선택이 맞지 않습니다` | 화면이 개편됨 | `--headed` 로 화면을 보고 '화면 구조 메모'의 요소를 다시 맞춘다 |
