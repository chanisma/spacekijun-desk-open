# 쿨메신저 쪽지 자동 발송

최종 검증: 2026-10-22 — CoolMessenger Gentoo **5.75.80.2**, Windows 11.

> ⚠️ **아래 값은 고정값이 아니다.** 컨트롤 id(`1656` `4362` `3249` …), 창 제목(`메시지 전송` `사용자 선택` `열기`),
> 버튼 캡션 접두어(`선택`/`해제`), DB 컬럼명은 쿨메신저 업데이트로 바뀔 수 있다. 어느 날 갑자기 "쪽지창이 안 열린다 / 버튼을
> 못 찾는다"면 버전이 바뀐 것이다 — 추측해서 누르지 말고 `native.ps1` 의 `Get-CmChildren` 으로 컨트롤을 덤프해 다시 맞춘다.

## 무엇을 하고, 무엇을 안 하는가

| 한다 | 안 한다 |
|---|---|
| 조직도에서 수신자 찾아 쪽지 작성·발송 (다중 수신자) | **로그인** — 꺼진 앱을 켜도 자동 로그인이 꺼져 있으면 로그인 창에서 사람이 로그인해야 한다 |
| 파일 첨부, 제목·본문(서식 HTML 포함) 입력 | 받은 쪽지 감시·알림·답장 |
| **쿨메신저가 꺼져 있으면 디버깅 포트로 켠다** (켜질 때까지 대기) | 켜져 있는 앱의 자동 재시작 (작성 중 쪽지창이 사라지므로 사람이 `-Restart` 로 결정) |
| 작성만 하고 대기 → 내용 확인 → 발송/폐기 | 예약 시각 지정 (`-ScheduleAt` 은 막아 둠 — 아래 함정 참고) |
| **발송 후 보낸 쪽지를 읽어 확인** (`check-sent.py`) | 쪽지 회수 (쿨메신저에 회수 기능이 없다) |

## 파일 구성

| 파일 | 역할 |
|---|---|
| `send-message.ps1` | **발송 본체.** 수신자 해석 → 쪽지창 → 제목 → 본문 → 첨부 → 보내기 → 발송 확인 |
| `send-held.ps1` | `-DryRun` 으로 띄워 둔 쪽지창을 읽어 보여 주고 `-Send` / `-Discard` |
| `check-sent.py` | **보낸 쪽지 읽기(읽기 전용).** 발송 후 확인, 본문·수신자·도착 시각 조회 |
| `roster.ps1` | 조직도 명부·별칭 관리 (`sync` `find` `alias` …) |
| `start-coolmessenger.ps1` | 쿨메신저를 디버깅 포트(9222)로 실행 |
| `style.ps1` · `message-style.template.md` | **문체 프로필** 관리 — 첫 사용 인터뷰 결과를 저장·조회 (`exists` `path` `show` `init`) |
| `install.ps1` | Claude Code / Codex 가 읽는 위치로 이 스킬을 설치 (`-Target claude\|codex\|both`) |
| `native.ps1` | 창 메시지 라이브러리 (트리 열거·클릭·창 찾기·메인 창 복원) — 위 스크립트가 불러 쓴다 |
| `cdp.js` | 쪽지 본문 에디터(CEF)에 붙는 의존성 없는 CDP 클라이언트 |

명부·별칭은 `%LOCALAPPDATA%\CoolMessengerSend\` (`roster.json`, `aliases.json`)에 저장된다. 스킬 폴더는 건드리지 않는다.

## 작업 순서 (에이전트가 따를 것)

1. **문체 프로필 확인** — `.\style.ps1 exists`. `no` 면 아래 **'처음 쓸 때'** 인터뷰부터. `yes` 면 `.\style.ps1 show` 를 읽고 그 문체로 쓴다.
2. **수신자 확인** — `.\roster.ps1 find 이름` 으로 실제 대상(대화명)을 확인한다. 특정되지 않으면 사용자에게 묻는다.
3. **초안 작성 → 사용자 확인** (아래 '발송 전 확인 게이트').
4. 승인 뒤에만 `-Confirmed` 를 붙여 `send-message.ps1` 로 발송.
5. 발송 뒤 `check-sent.py` 결과로 확인하고(수신자·본문·도착 즉시/예약) 사용자에게 보고한다.

## 처음 쓸 때 — 말투·구조 인터뷰

`.\style.ps1 exists` 가 `no` 일 때만 한다(사용자당 1회). 사람마다 문체가 달라서, 초안을 쓰기 전에 **어떤 말투·구조로 쓸지 먼저 묻고 그 지식을 남긴다.**
질문 도구가 있으면 쓰고 없으면 대화로 묻는다. 한 번에 2~4개씩, 선택지와 짧은 예시를 같이 보여 준다.

| 묶음 | 물어볼 것 |
|---|---|
| 말투 | 존댓말 정도(합쇼체 "~합니다" / 해요체 "~해요" / 섞음) · 이모티콘·기호 허용 범위(`:)` `ㅎㅎ` 등) · 문장 길이 |
| 시작과 맺음 | 고정 시작 문구 · 고정 맺음 문구 · 상대 호칭(`○○ 선생님` / 생략) |
| 구조 | 기본 순서(인사 → 요지 → 상세 → 요청·기한 → 맺음) · 줄글/번호 목록 · 길이 · **제목 쓰는 규칙** |
| 보조 | 상대별 차이(관리자·동료·학생·학부모) · 하지 않을 것 · 확인 생략을 허용할 범위(기본: 없음) |

- **샘플로 배우기(선택)**: "보낸 쪽지에서 문체를 참고해도 될까요?" 라고 묻고, **동의하면** `python .\check-sent.py --last 10 --body-chars 300` 으로 읽어 문체만 추정한다.
  추정한 규칙을 사용자에게 보여 주고 고치게 한다. **본문·이름·학생 정보는 저장하지 않는다** — 규칙과 일반화한 예시 문장만 남긴다.
- **저장**: `.\style.ps1 init` 으로 양식을 만들고 `.\style.ps1 path` 위치의 파일을 인터뷰 결과로 채운 뒤, 사용자에게 보여 확인받는다.
  프로필은 `%LOCALAPPDATA%\CoolMessengerSend\message-style.md` 에 있어 스킬을 다시 설치해도 남는다.
- **이후 교정**: 사용자가 초안을 고쳐 달라고 하면 고쳐 쓰고, `교정 이력` 에 한 줄 남긴다. 같은 지적이 반복되면 규칙에 반영할지 물어본다.

## 발송 전 확인 게이트 (필수)

**모든 쪽지는 초안을 보여 주고 승인을 받은 뒤에만 발송한다.** 수신자가 1명이어도, 짧아도 마찬가지다(프로필 `6. 발송 전 확인 규칙` 에 사용자가 직접 허용한 예외가 있을 때만 그 범위를 생략한다).

초안은 이 형식으로 보여 준다:

| 항목 | 내용 |
|---|---|
| 받는 사람 | `roster.ps1 find` 로 해석된 대상 (동명이인·대화명 주의) |
| 제목 | … |
| 본문 | (전문 그대로) |
| 첨부 | 파일명 또는 없음 |
| 도착 | 발송 전에는 알 수 없음 — 발송 뒤 `check-sent.py` 로 확인해 알려 드립니다 |

- 승인은 **"보내", "진행", "OK"** 처럼 분명한 말일 때만 인정한다. 질문·수정 요청·모호한 답은 승인이 아니다 — 고친 새 초안을 다시 보여 준다.
- **승인받은 본문과 같은 내용만** 발송한다. 승인 뒤 문구를 임의로 바꾸지 않는다.
- 스크립트가 강제한다: `send-message.ps1` 은 `-Confirmed` 가 없으면(작성만 하는 `-DryRun` 제외) UI 를 건드리기 전에 거부한다. **`-Confirmed` 는 사용자 승인 뒤에만 붙인다.**
- 에이전트의 권한 설정("승인 없이 실행" 등)과 무관하게 이 게이트는 지킨다 — 쪽지는 회수할 수 없다.

## 사전 조건

1. Windows + **CoolMessenger Gentoo** 설치. **자동 로그인**을 켜 두면 앱이 꺼져 있어도 스크립트가 켜서 로그인 창 없이 접속된다
   (꺼져 있으면 로그인 창이 뜨니 직접 로그인 — 스크립트가 최대 90초 기다린다)
2. 앱이 **`--remote-debugging-port=9222`** 로 떠 있어야 한다 — 본문이 CEF 에디터라 이게 없으면 본문을 못 넣는다
   - **앱이 꺼져 있으면** `send-message.ps1` / `roster.ps1 sync` 가 **알아서 이 포트로 켠다.**
   - **앱이 이미 켜져 있는데 포트가 없으면** 자동으로 재시작하지 않고 멈춘다(작성 중인 쪽지창이 사라지므로). 직접 정한다:
   ```powershell
   .\start-coolmessenger.ps1             # 포트가 이미 열려 있으면 확인만, 꺼져 있으면 켠다
   .\start-coolmessenger.ps1 -Restart    # 포트 없이 떠 있으면 종료 후 포트를 켜서 재시작 (작성 중 쪽지창은 사라짐)
   ```
3. **Node.js 22+** (`cdp.js` 가 내장 WebSocket 사용)
4. **Python 3** — 발송 확인(`check-sent.py`)에 필요. 없어도 발송은 되고, 확인 단계만 건너뛴다(경고가 뜬다)
5. PowerShell 5.1 이상. 스크립트 실행이 막혀 있으면 `Set-ExecutionPolicy -Scope Process Bypass`

## 사용법

```powershell
# ※ 반드시 `& .\스크립트` 로 호출한다. `powershell -File send-message.ps1 -To a,b` 는 배열이 문자열 하나로 넘어간다.
& .\send-message.ps1 -To "홍길동","인공지능실" -Title "제목" -Body "본문`n둘째 줄" `
    -Attach "C:\path\a.txt","C:\path\b.pdf"
# -BodyHtml "<p>서식 <b>본문</b></p>"   HTML 직접 지정
# -DryRun                               작성만 하고 보내지 않음 (창을 그대로 둔다)
# -Confirmed                            사용자가 초안을 확인·승인했음을 선언 — 발송에는 필수 (없으면 거부)

& .\send-held.ps1             # 대기 중인 쪽지창의 수신자·제목·본문·첨부 확인 (미발송)
& .\send-held.ps1 -Send       # 확인 후 발송
& .\send-held.ps1 -Discard    # 작성 취소 (닫기 확인 모달까지 처리)
```

## 🚨 안전 수칙 — 쪽지는 회수할 수 없다

1. **모든 쪽지는 발송 전에 초안(받는 사람·제목·본문)을 사람에게 보여 주고 승인을 받는다** ('발송 전 확인 게이트'). `-Confirmed` 없이는 스크립트가 발송을 거부한다.
   창에 올라간 실제 내용까지 확인하려면 `-DryRun` → `send-held.ps1` 로 확인 → `-Send` 순서를 쓴다.
2. 수신자를 **특정하지 못하면 발송이 멈춘다**(동명이인·대화명 불일치). 이름을 추측해서 보내지 말고 후보를 사용자에게 보여 준다.
3. 발송 후에는 반드시 **보낸 쪽지를 읽어 확인**한다(아래). 수신자 전원·본문 숫자·도착 시각(즉시/예약)을 눈으로 본다.
4. **"발송 확인 실패" 경고가 떠도 쪽지는 나갔을 수 있다.** 확인 전에는 재발송하지 않는다 — 같은 쪽지가 두 번 나간다.
5. 쪽지 본문·수신자 정보에는 개인정보가 들어 있을 수 있다. 확인에 필요한 만큼만 보고, 통째로 다른 곳에 복사·전송하지 않는다.
6. 이 도구는 **창을 자동 조작**한다. 소속 기관의 정보보안 정책이 메신저 UI 자동화를 허용하는지 먼저 확인한다.
   대량·반복 발송(스팸성 안내)에 쓰지 않는다.

## 수신자 이름 해석

조직도 표시는 `(대화명)메모` 형식이고 **대화명이 실명이 아닌 경우가 있다** — 예: 홍길동 선생님이 `(보건실)홍길동` 으로 등록돼 있으면
이름만으로는 트리에서 못 찾는다. 그래서 명부를 떠 두고 요청 이름을 실제 항목으로 바꾼다. `send-message.ps1` 이 자동으로 거친다.

```powershell
.\roster.ps1 sync                  # 조직도 → 명부 갱신 (인사이동·대화명 변경 뒤에 다시)
.\roster.ps1 find 홍길동           # 누구로 해석되는지 확인  ✅ '홍길동' → '(보건실)홍길동' (메모 일치)
.\roster.ps1 alias 홍길동 보건실   # 수동 매핑 (요청이름 → 대화명)
.\roster.ps1 list 보건 / aliases / unalias 홍길동
```

해석 순서: **별칭 → 대화명 완전일치 → 메모(실명) 완전일치 → 부분일치(결과가 하나일 때만)**. 부분일치가 여러 건이면
고르지 않고 후보를 돌려주고 멈춘다 — 엉뚱한 사람에게 가는 것보다 낫다. 명부는 캐시이므로 인사이동 뒤에는 `sync` 를 다시 돌린다.

## 발송 후 보낸 쪽지 읽기 (확인 단계)

`send-message.ps1` 과 `send-held.ps1 -Send` 는 발송 **직전의 마지막 `MessageKey`** 를 기록해 두고, 발송 뒤 `check-sent.py --after <그 키>` 로
**새로 생긴 보낸 쪽지**를 읽어 보여 준다. 쿨메신저의 로컬 DB(`%LOCALAPPDATA%\CoolMessenger\Memo\*.udb`, SQLite)의 `tbl_send` 를
**복사본으로 읽기 전용** 조회하므로 앱이 켜져 있어도 안전하고 원본은 건드리지 않는다.

```powershell
python .\check-sent.py                       # 최근 3건
python .\check-sent.py --last 10 --body-chars 200
python .\check-sent.py --after 1052          # 이 키보다 큰 것 = 방금 보낸 것
python .\check-sent.py --contains 홍길동     # 받는이·제목·본문에 든 것만
python .\check-sent.py --max-key             # 현재 마지막 키 (발송 전 기준점)
```

출력 예:
```
key=1053 | 발송 2026/10/22 10:47:04 (목) | 도착 즉시
  받는이: 홍길동(홍길동); 김철수(김철수);
  제목  : 안내
  첨부  : (없음)
  본문  : 안녕하세요 :) …
```

| 볼 것 | 의미 |
|---|---|
| `key` 가 기준점보다 **늘었는가** | 정말 나갔는지의 판정 기준 (제목 비교는 쓰지 않는다 — 아래 함정 1) |
| `받는이` | 수신자 전원이 들어 있는가 |
| `도착` | `즉시` 이면 바로 도착. **`예약 <시각>` 이면 그 시각에 도착**한다 → 사용자에게 도착 예정 시각을 알린다 |
| `본문` | `MessageText`(전문). 숫자·이름이 의도대로 들어갔는가 |

## 🚨 예약전송 함정

쿨메신저 새 쪽지창은 **예약전송이 기본 ON, 시각 = 현재 + 10분** 이다. 자동화로 보낸 쪽지가 이 예약으로 걸리면 10분 뒤에 도착한다.

- 2026-09-08 실측: 자동 발송 7건 전부 예약으로 걸렸다. 2026-10-13·10-22 오전에는 `예약전송=OFF` + `ScheduledDate` 빈 값(즉시)이었다.
  그러나 **같은 10-22 11:12 에는 `예약전송=ON`** 으로 떠서 10분 뒤(11:22)로 예약됐다(key 1060). 언제 ON 이 되는지 규칙을 모른다 —
  앱 재시작 뒤, 또는 작성창을 폐기한 직후에 ON 으로 돌아간 사례가 있다. → **매번 발송 뒤 `도착` 값을 확인**하고, `예약 …` 이면 도착 시각을 알린다.
  (발송 스크립트는 `예약전송=ON` 이면 발송 전에 경고하고, 발송 후 `check-sent.py` 가 `도착 예약 …` 으로 다시 알려 준다.)
- 예약 버튼들은 오너드로우(`BS_OWNERDRAW`)라 `BM_GETCHECK`/`BM_SETCHECK` 가 안 통한다. 상태는 **캡션 접두어**(`선택`=ON / `해제`=OFF)로만 읽는다.
- **토글하지 않는다.** 체크를 해제해도 예약이 그대로 걸린 적이 있고, 토글하면 수신자 칩이 지워진 채 `보내기` 가 조용히 무응답이 되는 일이 있다.
- 예약 시각을 바꾸는 `DTM_SETSYSTEMTIME` 은 값은 바뀌지만 `보내기` 가 무응답이 된다 → `-ScheduleAt` 은 지원하지 않는다(쓰면 오류).

## Claude Code · Codex 에서 쓰기

두 에이전트가 **같은 SKILL.md 형식**(`name` + `description` 필수, `scripts` 허용)을 읽는다. 다른 것은 **스킬을 찾는 위치**뿐이다.

| | Claude Code | Codex |
|---|---|---|
| 사용자 전체 | `~\.claude\skills\` | `~\.agents\skills\` |
| 특정 폴더·저장소 | `<repo>\.claude\skills\` | `<작업 폴더 ~ 저장소 루트>\.agents\skills\` |
| 설치 | `.\install.ps1 -Target claude` | `.\install.ps1 -Target codex` (둘 다: `-Target both`) |

설치 뒤에는 에이전트를 **새 세션으로 다시 시작**해야 스킬이 보인다. 특정 폴더에만 두려면 `-Scope repo -RepoPath <폴더>`.

### 🚨 Codex 는 샌드박스 밖에서 실행해야 한다

이 스킬은 **사용자 화면의 쿨메신저 창을 직접 조작**한다. Codex 의 기본 샌드박스(`workspace-write`, Windows 는 별도 데스크톱을 쓴다)에서는 그 창이 보이지 않는다.
2026-10-22 시험(codex-cli 0.163.0, `[windows] sandbox = "elevated"`):

| 환경 | 결과 |
|---|---|
| 샌드박스 안 (`-s workspace-write`) | `style.ps1` · `check-sent.py` · `roster.ps1 find` · `start-coolmessenger.ps1`(포트 확인) **성공**. `roster.ps1 sync` · `send-message.ps1` 은 **`쿨메신저 메인 창을 찾지 못했습니다`** 로 실패 |

→ **창을 조작하는 명령**(`send-message` `send-held` `roster sync` `start-coolmessenger -Restart`)은 샌드박스 밖에서 돌린다: Codex 를 `-s danger-full-access` 로 열거나, 승인을 받아 샌드박스 밖에서 실행한다.
`prefix_rule` 로 예외를 두는 방법은 쓰지 않는다 — Codex 가 명령을 `pwsh -Command "& .\스크립트 인자…"` 한 덩어리로 넘겨 인자별 지정이 어렵고, 공식 문서도 PowerShell 매칭을 보장하지 않는다.
샌드박스 안에서 창을 못 찾으면 앱을 다시 켜려 하지 말고(포트가 열려 있으면 스크립트가 원인을 알려 준다) 샌드박스 밖에서 다시 실행한다.

Claude Code 는 별도 설정이 필요 없다(일반 권한 확인).

## 동작 원리 (유지보수용)

`쿨메신저` 는 **MFC 네이티브 + 본문 에디터만 CEF** 인 앱이다. 그래서 역할이 갈린다.

| 단계 | 수단 |
|---|---|
| 메인 창 복원, 광고 팝업 닫기 | 창 메시지 (`ShowWindow`, `WM_CLOSE`) |
| 첫 수신자 → 쪽지창 열기 | 조직도 `SysTreeView32`(id 3013) 열거 → 선택 → `WM_LBUTTONDBLCLK` |
| 추가 수신자 | `받는사람`(Button 1656) → `사용자 선택` 창 트리(1400)·추가(1636)·선택된 사람(1401)·확인(3007) |
| 제목 | `Edit` 4362 ← `WM_SETTEXT` |
| **본문** | **CDP** `setHtml()` (`coolmsgrichtext.html`, iframe `#editFrame`) |
| 첨부 | `Button` 1449 → `열기` 창 `Edit` 1148 에 **전체 경로** → `Button` 1 |
| 보내기 | `Button` 3249 (**PostMessage**) |
| 확인 | `tbl_send` (`check-sent.py`) |

커서·포커스를 뺏지 않는 방식이라 사용자가 다른 작업을 해도 된다. 단, 발송하는 몇십 초 동안은 쿨메신저 창을 직접 조작하지 않는 편이 안전하다.

## 함정 (전부 실제로 겪음)

1. **`tbl_send.Title` 은 앞 약 29자만 저장된다.** 긴 제목은 DB 와 전체 일치 비교가 항상 실패한다 → 발송 판정은 **MessageKey 증가**로 한다.
2. **모달을 여는 버튼은 `PostMessage`.** `SendMessage` 로 누르면 대화상자가 닫힐 때까지 블록된다(180초 타임아웃 경험).
   받는사람·파일첨부·확인·열기·보내기가 해당.
3. **`GetWindowText` 는 다른 프로세스의 Edit 에서 빈 문자열**을 준다 → `SendMessage(WM_GETTEXT, buf)` 로 읽는다.
4. **`PostMessage`(ANSI)로 한글 `WM_CHAR` 를 보내면 깨진다** → `PostMessageW` 를 쓴다.
5. **트리 항목이 화면 밖이면 `TVM_GETITEMRECT` 좌표가 무효(음수)** → `TVM_ENSUREVISIBLE` + 맨 위로 스크롤해서 좌표를 양수로 만든다.
6. **32비트 앱이라 `TVITEM` 은 40바이트 레이아웃**이다.
7. **메인 창이 트레이로 숨겨지거나 최소화돼 있으면** 조직도를 읽지도(`조직도 트리를 찾지 못함`) 더블클릭하지도 못한다. 쪽지창이 **조용히** 안 열린다.
   → `Restore-CmMainWindow` 가 복원한다(`SetForegroundWindow` 는 쓰지 않는다 — 포커스를 뺏지 않으려고).
8. **작성창에 `WM_CLOSE` 를 보내면 '이 창을 닫으시겠습니까?' 모달**이 뜬다. 응답하지 않으면 남아서 앱을 막는다 → `Button` 5025(확인)를 처리한다(`send-held -Discard` 가 한다).
9. **수신자 입력칸에 이름을 타이핑 + Enter** 는 조직도에 **유일한** 이름만 확정된다. 동명이인은 확정되지 않는다 → 트리 선택 방식을 쓴다.
10. **조직도 항목을 더블클릭 반복**으로 수신자를 추가하면 추가되지 않고 쪽지창이 하나 더 열린다 → `사용자 선택` 창을 쓴다.
11. **Playwright `connectOverCDP` 는 쿨메신저(CEF 91)에 못 붙는다**(`Browser context management is not supported`). 페이지 타깃 WebSocket 에 직접 붙는 `cdp.js` 를 쓴다.
12. **버튼 캡션 반영에 시간이 걸린다.** `BM_CLICK` 뒤 약 2.5초 기다려야 1클릭=1토글로 읽힌다.
13. **🚨 조직도 위 검색칸에 검색어가 남아 있으면 조직도가 검색 결과로 걸러진다.** (2026-10-22: 사용자가 한 명을 검색해 두고 닫은 뒤, `학교 > 부서 > 동료 1명` 한 명만 보여
    6명 발송이 전부 `트리에서 못 찾음`으로 멈췄다. 아무것도 발송되지 않아 안전했지만, `roster.ps1 sync` 가 **92명 명부를 1명으로 덮어썼다**.)
    - 검색칸(`Edit` 1708)은 **비어 있어도 안내 문구(`이름(아이디) 또는 그룹명 검색`)가 들어 있다** — 글자 수만 보면 늘 "남아 있다"로 오판한다. 안내 문구는 빈 것으로 본다.
    - 칸의 글자를 직접 지우면(`WM_SETTEXT ''`) 앱의 안내 문구 상태가 깨져 조직도가 오히려 접힌 채 남았다 → **칸은 건드리지 않고** 앱의 `검색초기화(ESC)` 단추(3278)만 누른다 (`Reset-CmSearch`).
    - `Sync-CmRoster` 는 새로 읽은 사람이 기존 명부의 절반 미만이면 **덮어쓰지 않고 멈춘다.** 걸러진 조직도로 명부를 망가뜨리지 않기 위한 안전장치다.
